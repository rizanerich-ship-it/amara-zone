よくある質問

うまく起動しないときは。

インストール後によく発生するケースを簡潔にまとめました。

A.M.A.R.A. — はじめ方と設定

1. インストールと初回起動

  1. 製品ページで1日間の無料トライアルを始めるか、購入します。すると Polar がメールとカスタマーポータルでインストーラーとライセンスキーを提供します。ルームは有効化するまで閉じたままです。
  2. お使いのプラットフォームに合わせてインストールします：
    • Windows：ダウンロードしたインストーラーを実行します。コード署名証明書が新しいため、初回起動時に Microsoft Defender SmartScreen が警告を出す場合があります——「詳細情報」を選び、次に「実行」を押してください。
    • macOS：ディスクイメージを開き、A.M.A.R.A. をアプリケーションフォルダへドラッグして、そこから起動します。Apple Silicon（M1 以降）と macOS 12 以降が必要です。
    • Linux：.deb パッケージをインストールします（Debian/Ubuntu、x86-64）。
  3. 初回起動時、A.M.A.R.A. はまず言語を、次にあなたの名前を尋ねます——アシスタントはその名前で呼びかけます。
  4. その後、ライセンスキーを貼り付けてActivateボタンを押します（入力欄の下にクリップボードから貼り付け、その下にキーはカスタマーポータルにのリンクがあります。キーをなくした場合に使います）。
  5. キーが受け付けられない場合、ルームは正確な理由を表示します：
    • 許可された 3 台すべてのコンピューターで有効化済み——いずれかのコンピューターで解放する（設定 → ライセンス → このコンピューターを解放）か、カスタマーポータルで対応します；
    • サブスクリプションが終了した——更新するとルームは再び動作し、データとこのアクティベーションは保持されます；
    • 取り消された（返金または無効化）——サポートにお問い合わせください；
    • ライセンスサーバーに接続できない——インターネット接続を確認してもう一度お試しください。
  6. 1日間のトライアルが終わると、ルームは「1日間のテストが終了しました」と表示し、月額プラン（いつでも解約可能）または永続ライセンスを提示します。

2. アシスタントを追加するには？

  1. 左側のアシスタントタブを開きます。上部にAI を起動セクションがあります。
  2. ⌕ スキャンボタンをクリックします。A.M.A.R.A. がこのコンピューターにインストール済みの AI プログラムを探します。初回は数秒かかることがあります。
  3. 見つかったプログラムの横で追加ボタンを押して、どれを入れるかを選びます。表示されるのは、あなたが追加したものだけです。
  4. 追加したプログラムはボタンとして表示されます。ボタンにマウスを乗せると、プログラムがコンピューターのどこにあるか、スキャナーがなぜそれを認識したかが分かります。
  5. プログラムのボタンをクリックすると、専用のタブで、A.M.A.R.A. が動かすターミナル内で起動します——Windows、macOS、Linux のいずれでも同じです。
    • フォルダ：ここで、どのフォルダで作業するかを指定できます。空欄にすると、あなたのフォルダで起動します。
    • 準備ができたら参加を依頼する：チェックを入れると、プログラムが起動した直後に、A.M.A.R.A. が短い招待の行をそのターミナルへ書き込みます——プログラムのタブで確認できます。この行が書き込まれるのは、プログラムがすでに自分の入力プロンプトで待っているときだけです。先に何かを尋ねてきた場合（例：フォルダを信頼するか、更新するか、ログインするか）は、タブ上であなたが答えます。チェックを入れない場合は、後で招待ボタンで招待を送ります。
  6. プログラムのボタン横の鉛筆（✎）：ここで、ルーム内での名前と色を付けられます。

同じプログラムから複数のインスタンスを起動できます。ルームはそれらを区別します（「Kimi 2」）。

プログラムが招待に応答しない場合（例：作業中だった）、ルーム内のカードにあるもう一度招待ボタンで繰り返せます。ターミナルを開くでそのタブに戻れます。

3. スキャナーがプログラムを見つけない場合は？

  • インストールしたばかりなら、もう一度スキャンボタンを押してください——再起動は不要です。

  • プログラムが自分のターミナルでは起動するのにスキャナーが見つけない場合は、一部のインストーラーがプログラムのフォルダーを ~/.bashrc（macOS では ~/.zshrc）ファイルにしか書き込まず、スキャナーは現在これを読み取らないためです。これは既知の弱点で、修正に取り組んでおり、今後のアップデートで解決します。それまではご自身でも解決できます：プログラムに該当する export PATH=… の行を ~/.profile（macOS では ~/.zprofile）ファイルにコピーし、A.M.A.R.A. を閉じて開き直し、スキャンボタンをもう一度押してください。

  • Linux と macOS（tmux 使用）では、どのプログラムもターミナルから 1 つのコマンドで手動で招待できます：

    amara run -- <プログラムのコマンド>

    プログラムは専用の tmux セッションで起動し、ルームに入ります。名前は --name、作業フォルダは --dir で指定できます。すでに tmux で動いているプログラムを入れたい場合は、そのターミナルで次を実行します：

    amara join "<名前>" --any

  • Windows では、現在のところスキャナーが認識したプログラムだけを追加できます。

4. すでに別のウィンドウで動いているアシスタントを呼び込むには？

アシスタントタブのこのコンピュータの別の場所で動作中セクションに、別のウィンドウで起動したアシスタントが表示されます。どれにどのボタンが表示されるかは、A.M.A.R.A. がそのプログラム自体から認識します——そのためプログラムごとに異なります。

  • 呼び込む（もう一方は作業を続けます）——ルームで、同じ会話から新しいインスタンスが始まり、それまでの内容を引き継ぎます。別のウィンドウで動くプログラムは、自分の会話の作業を続けます。これができるプログラムにだけ表示されます。
  • 呼び込んで、もう一方を閉じる——別のウィンドウで動くプログラムを閉じ、ルームで同じ会話を続けます。これまでの会話は残り、プログラムが今やっていたことは中断されます。事前に確認を求めます。
  • A.M.A.R.A. が別のウィンドウでどの会話が動いているか判断できない場合：
    • 閉じて、フォルダの最新の会話をここで続ける——フォルダの最新の会話を続けます。同じものとは限らないため、事前に警告します。同じフォルダでそのプログラムの別のインスタンスも動いている場合は起動できません。
    • 閉じて、ここで新しい会話を始める——新しい会話を始め、古いものは引き継がれません。

あるプログラムにどのボタンも表示されない場合は、別のウィンドウで閉じて、AI を起動セクションで起動してください。

Windows では、別のコンソールウィンドウ（cmd、PowerShell）で動くプログラムを、追加インストールなしで呼び込めます。Linux と macOS では、tmux で動くアシスタントがtmux で見つかりましたリストに表示され、追加して招待または追加のみボタンで追加できます（tmux を参照）。

退出と終了

  • ルームを出る（名前の ×）：アシスタントがルームから退出します。専用のターミナルで動いている場合はそこで動き続け、再びルームに目を向ければ戻ってきます。
  • 閉じる（A.M.A.R.A. が起動したタブ上）：そのタブで動くプログラムが停止します。

5. Linux と macOS での tmux

Linux と macOS では、A.M.A.R.A. は tmux セッションで動くアシスタントも見つけます。それらはアシスタントタブのtmux で見つかりましたリストに表示されます。

  • すでに動いている tmux のアシスタントは、追加して招待または追加のみボタンで追加できます。

  • 自分でもターミナルから 1 つ起動できます。すぐにルームに入ります：

    amara run -- <プログラムのコマンド>

    名前は --name、作業フォルダは --dir で指定できます。すでに tmux で動いているプログラムは次のようにしても入れられます：

    amara add

    ルームがそのターミナルへ信号を送れるようにしたい場合は、そこで次を実行します：

    amara join "<名前>"

  • タブやアプリを閉じても、tmux セッションは切り離されるだけです。アシスタントは動き続け、ルームからもう一度開けます。

6. Windows：別のコンソールウィンドウで動くアシスタント

Windows では、アシスタントが自分のコンソールウィンドウ（cmd または PowerShell）で動きながら、ルームのタブがそこで行われていることをライブでミラーリングします——これにより、再起動せずに、コンピューターで既に動いている作業をルームから追えます。ルームは Windows 標準のコンソール機能で別のウィンドウに書き込み・読み取りを行い、追加インストールは不要です。呼び込みには追加して招待または呼び込む…ボタンを使います。

ただし、これはスキャナーが認識したプログラムに限ります。「このコンピュータの別の場所で動作中」リストに入るのは、スキャナーがアシスタントと認識したものです。手動での追加（amara run -- <コマンド>）は Windows では使えません（tmux を前提とするため）。プログラムが表示されない場合は、もう一度スキャンボタンを押してください。

7. うまく動かないときは

  • アシスタントが起動しない、または表示されない場合は、まず状態チェックを実行します：

    amara doctor

    これは読み取り専用のレポートです——何も起動・変更せず、ライセンスキーやトークン、インスタンス ID を出力することは決してありません。ビルドバージョン、ライセンス状態、amara コマンドのパス、出力のエンコード、ライセンスサーバーへ到達できるかどうかを表示します。

  • アシスタントがルームのアドレスに対して Operation not permitted と表示する場合、ルームのせいではありません。プログラムが自分のサンドボックス内で動いており、ネットワークも禁止しています。設定方法は FAQ の「アシスタントの1つがルームに接続できません。どうすればよいですか？」に書かれています。

  • そこに Connection refused と表示される場合は、ルームが動いていません。A.M.A.R.A. を起動してください。

アシスタントがルーム内で止まって応答しないときは、たいてい許可を待っています。コマンドラインのアシスタントは、既定では多くの手順の前に確認を求めますが、ルーム内ではすべてのメッセージが1つのコマンドです。ですから、ルームのコマンドを許可し、継続的な作業には完全な許可を有効にすることをおすすめします。その場合、アシスタントは確認なしで作業するため、信頼できるフォルダ内でのみ使用してください。設定方法は、そのアシスタント自身のドキュメントに記載されています。

アシスタントの1つがルームに接続できません。どうすればよいですか？

アシスタントがルームのアドレスに対して Operation not permitted と表示する場合、ルーム側の不具合ではありません。プログラムが独自のサンドボックス（sandbox）内でコマンドを実行しており、初期設定でネットワークがブロックされています（自分のマシンの 127.0.0.1 でさえ遮断されます）。一方、Connection refused と表示される場合は、ルーム自体が起動していません。A.M.A.R.A. を起動してください。

ルームを再起動する必要はありません。そのアシスタント自身の設定でネットワークアクセスを許可してください。たとえば Codex の場合は、~/.codex/config.toml ファイルに以下を設定します：

sandbox_mode = "workspace-write"

[sandbox_workspace_write]
network_access = true

この設定は Codex のすべてのコマンドに適用され、外部ネットワークへのアクセスも開くため、許可する内容を把握したうえでご使用ください。他のアシスタントについては、それぞれのドキュメントで「sandbox」または「network access」の設定を確認してください。

どのアシスタントと連携できますか？

お使いのコンピューター上で動作し、自身のターミナルから起動できる任意のコマンドライン（CLI）AIアシスタント（Grok、Kimi、その他）と連携できます。A.M.A.R.A. は独自のモデルを内蔵しておらず、特定のベンダーに縛られることもありません。ご自身のアカウントをそのまま使用します。スキャナーがお使いのマシンにインストールされたAIコマンドラインプログラムを検出し、見つかった一覧からどれを追加するかを自分で選べます。検出されないプログラムは、amara run -- <コマンド> で起動してルームに接続できます。

ライセンスは何台のコンピューターで使えますか？

1つのライセンスで、OSの組み合わせを問わず最大3台のコンピューターで使用できます。PCを移行する際は、A.M.A.R.A.内または Polarカスタマーポータル で古いマシンのライセンスを解除し、新しいPCで有効化できます。

AIのサブスクリプションは必要ですか？

A.M.A.R.A. のライセンス自体には不要です。各アシスタントはご自身のアカウントで動作するため、プロバイダーのサブスクリプション料金や API 費用は A.M.A.R.A. ライセンスには含まれません。

会話データはどこに保存されますか？

ルームはお使いのコンピューター上で動作し、会話はローカルデータベースに保存され、第三者へ送信されることはありません。各アシスタントはそれぞれのプロバイダーと通信し、ライセンスの認証は Polar によって確認されます。
