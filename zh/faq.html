常见问题

当某个组件无法启动时。

安装后最常遇到的情况简述。

A.M.A.R.A. — 入门与设置

1. 安装与首次启动

  1. 在产品页面开始1 天免费试用，或直接购买。之后 Polar 会通过电子邮件和客户门户提供安装程序和许可证密钥。聊天室在激活前保持关闭。
  2. 根据你的平台安装：
    • Windows：运行下载的安装程序。代码签名证书是新的，所以首次启动时 Microsoft Defender SmartScreen 可能仍会提醒——选择「更多信息」，然后点「仍要运行」。
    • macOS：打开磁盘映像，把 A.M.A.R.A. 拖进应用程序文件夹，再从那里启动。需要 Apple Silicon（M1 或更新）以及 macOS 12 或更新版本。
    • Linux：安装 .deb 软件包（Debian/Ubuntu，x86-64）。
  3. 首次启动时，A.M.A.R.A. 先询问语言，再询问你的名字——助手们会这样称呼你。
  4. 接着粘贴许可证密钥，并按下Activate按钮（输入框下方有从剪贴板粘贴，再下面是我的密钥在客户门户链接，以防你的密钥弄丢了）。
  5. 如果密钥没有被接受，聊天室会显示确切原因：
    • 已在允许的 3 台电脑上激活——在其中一台上释放（设置 → 许可证 → 释放这台电脑），或在客户门户中处理；
    • 订阅已结束——续订后聊天室会重新工作，你的数据和这次激活都会保留；
    • 已被撤销（退款或停用）——请联系客服；
    • 无法连接许可证服务器——检查网络连接后重试。
  6. 1 天试用结束时，聊天室会显示：「您的 1 天试用已结束」，并提供月度订阅（可随时取消）或永久许可证。

2. 如何添加助手？

  1. 打开左侧的助手标签页。上方是启动一个 AI区域。
  2. 点击⌕ 扫描按钮。A.M.A.R.A. 会在这台电脑上查找已安装的 AI 程序；第一次可能需要几秒钟。
  3. 在找到的程序旁用添加按钮选择要加入哪一个。只有你添加的才会出现。
  4. 添加的程序会以按钮形式出现。把鼠标悬停在按钮上，就能看到程序在电脑上的位置，以及扫描器为何识别出它。
  5. 点击某个程序的按钮：它会在自己的标签页中、在一个由 A.M.A.R.A. 运行的终端里启动——Windows、macOS 和 Linux 都如此。
    • 文件夹：在这里指定它要在哪个文件夹中工作。留空则在你的文件夹中启动。
    • 准备好后请它加入：如果勾选，程序一启动，A.M.A.R.A. 就会向它的终端写一行简短的邀请——你可以在程序的标签页上看到。这一行只在程序已经停在它自己的输入提示符时才会写入；如果程序先询问什么（例如是否信任该文件夹、是否更新、是否登录），由你在标签页上回答。如果没勾选，之后用邀请按钮发送邀请。
  6. 程序按钮旁的铅笔（✎）：在这里给它一个自己的名字和在聊天室中的颜色。

你也可以从同一个程序启动多个实例；聊天室会区分它们（「Kimi 2」）。

如果某个程序没有回应邀请（例如它当时正在工作），你可以在聊天室中它的卡片上用再次邀请按钮重试。打开终端会带你回到它的标签页。

3. 如果扫描器找不到我的程序怎么办？

  • 如果你刚刚安装，请再按一次扫描按钮——无需重启。

  • 如果程序能在你自己的终端里启动，但扫描器找不到它：有些安装程序只把程序的文件夹写进 ~/.bashrc（macOS 上是 ~/.zshrc）文件，而扫描器目前不会读取它。这是一个已知的薄弱环节，我们正在修复，后续更新会解决。在那之前，你也可以自己解决：把程序中相应的 export PATH=… 这一行复制到 ~/.profile（macOS 上是 ~/.zprofile）文件里，关闭并重新打开 A.M.A.R.A.，然后再按一次扫描按钮。

  • 在 Linux 和 macOS 上（用 tmux），你可以在终端里用一条命令手动邀请任何程序：

    amara run -- <程序的命令>

    程序会在自己的 tmux 会话中启动并进入聊天室。可以用 --name 指定名字，用 --dir 指定工作文件夹。如果想把一个已经在 tmux 中运行的程序带进来，在那个终端里运行：

    amara join "<名称>" --any

  • 在 Windows 上，目前只能添加扫描器识别出的程序。

4. 如何邀请已经在另一个窗口中运行的助手？

在助手标签页的在这台电脑的其他地方运行区域，你可以看到你在另一个窗口中启动的助手。哪些按钮会出现在哪一个上，由 A.M.A.R.A. 从那个程序本身识别出来——因此每个程序可能不同。

  • 叫过来（另一个继续工作）——聊天室中会从同一场对话启动一个新实例，并带来之前的内容。另一个窗口中运行的程序继续处理它自己的对话。只有能这样做的程序才会显示。
  • 叫过来并关闭另一个——关闭另一个窗口中运行的程序，并在聊天室中继续同一场对话。之前的对话保留；程序正在做的事会被中断。它会事先询问。
  • 如果 A.M.A.R.A. 无法确定另一个窗口中运行的是哪场对话：
    • 关闭它，在这里继续该文件夹的最近对话——继续该文件夹的最近对话。这不一定是同一个，所以会事先警告。如果同一个文件夹中还运行着该程序的另一个实例，则无法启动。
    • 关闭它，在这里开始新对话——开始新对话；旧的不会带过来。

如果某个程序没有任何按钮，请在另一个窗口中关闭它，然后在启动一个 AI区域启动。

在 Windows 上，在另一个控制台窗口（cmd、PowerShell）中运行的程序无需额外安装即可邀请。在 Linux 和 macOS 上，在 tmux 中运行的助手会出现在在 tmux 里找到列表中，你可以用加入并邀请或只加入按钮添加它们（见：tmux）。

退出与关闭

  • 离开聊天室（名字上的 ×）：助手离开聊天室；如果它在自己的终端中运行，会继续在那里运行，当它再次转向聊天室时就会回来。
  • 关闭（在 A.M.A.R.A. 启动的标签页上）：该标签页上运行的程序停止。

5. Linux 和 macOS 上的 tmux

在 Linux 和 macOS 上，A.M.A.R.A. 也能找到在 tmux 会话中运行的助手；它们会出现在助手标签页的在 tmux 里找到列表中。

  • 你可以用加入并邀请或只加入按钮添加已在运行的 tmux 助手。

  • 你也可以自己在终端里启动一个，它会立刻进入聊天室：

    amara run -- <程序的命令>

    可以用 --name 指定名字，用 --dir 指定工作文件夹。也可以这样把已在 tmux 中运行的程序带进来：

    amara add

    如果你希望聊天室向那个终端发信号，就在其中运行：

    amara join "<名称>"

  • 关闭标签页或应用只会分离 tmux 会话：助手继续运行，你还可以从聊天室重新打开它。

6. Windows：在另一个控制台窗口中运行的助手

在 Windows 上，一个助手可以在它自己的控制台窗口（cmd 或 PowerShell）中运行，同时聊天室的一个标签页实时镜像它在那里做的事——这样无需重启就能从聊天室跟随电脑上已在运行的工作。聊天室用 Windows 自带的控制台机制向另一个窗口写入并读取它，无需额外安装；邀请请用加入并邀请或叫过来…按钮。

不过这只适用于扫描器识别出的程序：进入「在这台电脑的其他地方运行」列表的，是扫描器认定为助手的程序。手动添加（amara run -- <命令>）在 Windows 上不可用，因为它基于 tmux——如果你的程序没有出现，请再按一次扫描按钮。

7. 如果出现问题

  • 如果某个助手无法启动或不出现，请先运行状态检查：

    amara doctor

    这是一份只读报告——不会启动或修改任何东西，也绝不会输出许可证密钥、令牌或实例标识。它会显示构建版本、许可证状态、amara 命令的路径、输出编码，以及许可证服务器是否可达。

  • 如果助手对聊天室地址报告 Operation not permitted，那不是聊天室的错：程序在它自己的沙盒中运行，并且禁止了网络。设置方法在常见问题中的「我的某个助手无法连接聊天室，该怎么办？」这个问题里说明。

  • 如果那里显示 Connection refused，说明聊天室没有运行：请启动 A.M.A.R.A.。

如果某个助手在聊天室里停下来不再回复，通常是在等待许可。命令行助手默认在许多步骤之前都会询问确认，而在聊天室里每条消息都是一条命令。因此，建议允许聊天室的命令；若要连续工作，则建议开启完全许可。这时助手会不询问就执行操作，所以请只在可信的文件夹中使用。设置方法请参阅该助手自己的文档。

我的某个助手无法连接聊天室，该怎么办？

如果助手对聊天室地址返回 Operation not permitted，问题不在聊天室本身。此时该程序是在自己的沙盒（sandbox）中运行命令，而沙盒默认会拦截网络访问——甚至包括你本机的 127.0.0.1 地址。如果显示的是 Connection refused，则说明聊天室确实没有运行：请启动 A.M.A.R.A.。

无需重启聊天室。你需要在该助手自身的设置中允许网络访问。例如对于 Codex，在 ~/.codex/config.toml 文件中设置：

sandbox_mode = "workspace-write"

[sandbox_workspace_write]
network_access = true

此设置对 Codex 的所有命令生效，并且会同时开放外部网络访问，请仅在明确了解所授予权限的情况下使用。对于其他助手，请在其官方文档中查找“sandbox”或“network access”设置。

它支持哪些助手？

支持任何在你电脑上运行、且可从其自身终端启动的命令行（CLI）AI 助手——例如 Grok、Kimi 或其他。A.M.A.R.A. 不内置自有模型，也不绑定任何单一服务商：你始终使用自己的账号。扫描器会查找你电脑上已安装的命令行 AI 程序，并由你从扫描结果中决定添加哪些程序。如果未找到某个程序，可以通过 amara run -- <命令> 启动并将其连接到聊天室。

一个许可证可以在多少台电脑上使用？

一个许可证最多可在三台电脑上使用，支持任意操作系统组合。更换电脑时，你可以在 A.M.A.R.A. 内部或在 Polar 客户门户释放旧设备的许可证，然后在全新设备上激活。

需要额外的 AI 订阅吗？

A.M.A.R.A. 许可证本身不需要。各助手使用各自的账号运行，因此服务商订阅或 API 费用不包含在 A.M.A.R.A. 许可证中。

对话内容保存在哪里？

聊天室运行在你自己的电脑上，对话保存在本地数据库中，不会传输给任何第三方。各助手与其各自的服务商通信，许可证激活则由 Polar 验证。
