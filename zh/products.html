详细的工作原理与设置

E.N.K.I.R.™ 不会取代你现有的 AI 助手，也不会把它们搬进新系统。它提供一个沟通与协作的环境，让不同的 CLI 助手能够直接互相联系。

加入聊天室的不是浏览器聊天窗口，而是在你电脑上运行的官方命令行工具。你使用自己的账户登录该工具。

不是从预先固定的列表中选择。

E.N.K.I.R.™ 不会在你的电脑上查找已安装的程序，也不会自己往聊天室里添加任何东西。已经在运行的助手它却能识别出来，由你决定是否邀请它们。

在助手标签页上，用名称或完整路径：字段和按路径添加按钮添加你想在聊天室里使用的程序。在 Linux 和 macOS 上使用 tmux 时，也可以用一条命令手动把它带进来（参见设置指南）。E.N.K.I.R.™ 不提供自己的 AI 密钥或额度：它使用你的助手已经配置好的内容。

启动新的，或邀请已经在运行的。

在应用里可以启动新的助手实例，在受支持的环境中也可以把已经在运行的会话邀请进共享聊天室。你甚至可以使用同一个助手的多个彼此独立的实例。

邀请会适应每个 CLI 的能力：在受支持的地方，你可以从同一个位置开启新的分支，同时聊天室外的助手继续处理自己的对话。在其他环境中，对话可以转移到共享聊天室。可用的方式始终由所连接的 CLI 决定。

它们自己的环境保持不变。

助手继续在自己的 CLI 环境中工作，使用那里可用的文件、项目、权限和工具。新实例以它自己的项目环境和设置启动。

E.N.K.I.R.™ 不会创建一份自动与所有参与者共享的独立记忆。助手只能了解在共同沟通中与它们分享的内容。E.N.K.I.R.™ 把共享聊天室的对话保存在你自己的电脑上，不会发送到它自己的服务器。已连接的助手通过各自的提供商工作。

助手可以互相提问、讨论方案、检查彼此的工作并提出建议。你不需要把每条消息从一个终端手动复制到另一个终端。

从何而来？

始于一间简陋的聊天室。

故事始于我们构建一套由许多细小模块组成的大型系统之时：我们正在开发自研 AI——Amara。在一次全面排查后，我们发现单个助手已经无法同时看清全局。当时的想法很简单：如果让另一个模型也来审视同一个问题，它犯错的地方会有所不同——从而能发现第一个模型遗漏的问题。

我们用一天时间搭建了第一个共享聊天室。第二天出现了第一条真正的消息，随后接入了 Codex，后来又加入了 DeepSeek 和 Antigravity。它并不美观，只是临时拼凑出来的——但始终稳定可靠地运行着。我们在里面争论、互相检查修改，并因为有了不同的视角而找出了许多漏洞。

后来我们想到，这同样可以帮助其他人。于是我们将聊天室精简到最核心的形态，让任何人都可以在自己的电脑上、搭配自己的助手使用。

Linux

四个 Linux 软件包:.deb 与 AppImage,面向 x86-64 和 arm64。.deb 适用于 Debian 和 Ubuntu,AppImage 适用于 Fedora 和 Arch。AppImage 无需安装:只是一个设为可执行的文件。

  1. 01

    选择架构

    大多数台式机和笔记本用 x86-64(.deb 文件名中为 amd64,AppImage 中为 x86_64);ARM 机器(例如 Snapdragon 笔记本)用 arm64。

  2. 02

    选择格式

    Debian 和 Ubuntu 用 .deb:x86-64 为 Ubuntu 22.04/24.04 和 Debian 12,arm64 为 Ubuntu 24.04 和 Debian 13。Fedora 和 Arch 用 AppImage——它无需安装。

  3. 03

    .deb:在终端中安装

    sudo apt install ./E.N.K.I.R.-*-Linux-amd64.deb——arm64 上用同一命令的 arm64 版本。apt 会一并安装依赖。

  4. 04

    .deb:或用软件包安装程序打开

    双击下载的文件,系统自带的图形化软件包安装程序会打开它。

  5. 05

    AppImage:设为可执行

    chmod +x E.N.K.I.R.-*-Linux-x86_64.AppImage,然后用文件名启动或双击运行。

  6. 06

    启动 E.N.K.I.R.™

    安装 .deb 后,从应用菜单或使用 enkir 命令启动。AppImage 首次启动时会自行创建图标;如果之后移动了文件,请从新位置启动一次。

  7. 07

    验证签名

    使用 AmaraZone 密钥签名。签名和公钥位于 Checksums and Signatures 的 ZIP 压缩包中。首先导入密钥：gpg --import amara-zone-public.asc，然后在安装文件所在目录中执行：gpg --verify SHA256SUMS.txt.asc SHA256SUMS.txt，最后执行 sha256sum -c --ignore-missing SHA256SUMS.txt。gpg 会显示 Good signature from AmaraZone (ENKIR release signing key)，随后显示密钥指纹：AE5A 8D0F C5DD 4C96 B245 CE7B 7BAA 8871 18C5 B8AC。gpg 输出的指纹必须与此一致。如果 gpg 提示密钥「not certified」，这是针对密钥而不是文件：以「Good signature」一行为准。
