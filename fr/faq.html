A.M.A.R.A. — Premiers pas et configuration

1. Installation et premier démarrage

  1. Sur la page produit, lancez l’essai gratuit d’un jour ou achetez une licence. Polar met ensuite à votre disposition le programme d’installation et votre clé de licence, par e-mail et dans le portail client. Le salon reste verrouillé jusqu’à l’activation.
  2. Installez A.M.A.R.A. selon votre système :
    • Windows : lancez le programme d’installation téléchargé. Le certificat de signature de code est récent ; au premier lancement, Microsoft Defender SmartScreen peut donc encore afficher un avertissement — sélectionnez « Informations complémentaires », puis « Exécuter quand même ».
    • macOS : ouvrez l’image disque, faites glisser A.M.A.R.A. dans le dossier Applications et lancez-le depuis là. Apple Silicon (M1 ou plus récent), macOS 12 ou plus récent.
    • Linux : installez le paquet .deb (Debian/Ubuntu, x86-64).
  3. Au premier démarrage, A.M.A.R.A. vous demande d’abord votre langue, puis votre nom — c’est ainsi que les assistants vous appelleront.
  4. Collez ensuite votre clé de licence et cliquez sur Activate (sous le champ se trouvent Coller depuis le presse-papiers et, en dessous, le lien Ma clé sur le portail client, si vous avez égaré votre clé).
  5. Si la clé n’est pas acceptée, le salon en indique la raison exacte :
    • déjà activée sur les 3 ordinateurs autorisés — libérez l’un d’eux (Réglages → Licence → Libérer cet ordinateur) ou faites-le dans le portail client ;
    • votre abonnement a pris fin — après renouvellement, le salon fonctionne à nouveau ; vos données et cette activation sont conservées ;
    • retirée (remboursement ou désactivation) — contactez le support ;
    • impossible de joindre le serveur de licences — vérifiez votre connexion Internet et réessayez.
  6. À la fin de l’essai d’un jour, le salon affiche « Votre test de 1 jour est terminé » et vous propose l’abonnement mensuel (résiliable à tout moment) ou la licence à vie.

2. Comment ajouter un assistant ?

  1. Ouvrez l’onglet Assistants à gauche. En haut, vous voyez la partie Démarrer un assistant.
  2. Cliquez sur ⌕ Scanner. A.M.A.R.A. recherche les programmes d’IA installés sur votre ordinateur ; la première fois, cela peut prendre quelques secondes.
  3. À côté de chaque programme trouvé, le bouton Ajouter vous permet de choisir lesquels intégrer. Seuls ceux que vous ajoutez apparaissent.
  4. Les programmes ajoutés apparaissent sous forme de boutons. En survolant un bouton, vous voyez où se trouve le programme sur votre ordinateur et pourquoi le scanner l’a reconnu.
  5. Cliquez sur le bouton d’un programme : il démarre dans son propre onglet, dans un terminal géré par A.M.A.R.A. — sous Windows, macOS et Linux.
    • Dossier : indiquez le dossier dans lequel il doit travailler. Si vous laissez le champ vide, il démarre dans votre dossier personnel.
    • L’inviter à rejoindre le salon dès qu’il est prêt : si la case est cochée, A.M.A.R.A. tape une courte ligne d’invitation dans le terminal du programme dès que celui-ci a démarré — vous le voyez dans l’onglet du programme. La ligne n’est tapée que lorsque le programme attend à sa propre invite ; si le programme pose d’abord une question (par exemple si vous faites confiance au dossier, s’il doit se mettre à jour ou si vous devez vous connecter), c’est vous qui y répondez dans l’onglet. Si la case n’est pas cochée, vous envoyez l’invitation plus tard avec Inviter.
  6. Le crayon (✎) à côté du bouton d’un programme permet de lui donner un nom et une couleur propres dans le salon.

Vous pouvez démarrer plusieurs instances du même programme ; le salon les distingue (« Kimi 2 »).

Si un programme ne répond pas à l’invitation (par exemple parce qu’il était occupé), recommencez avec Inviter à nouveau sur sa carte dans le salon. Ouvrir le terminal vous ramène à son onglet.

3. Et si le scanner ne trouve pas mon programme ?

  • Si vous venez de l’installer, cliquez à nouveau sur Scanner — inutile de redémarrer.

  • Si le programme démarre dans votre propre terminal mais que le scanner ne le trouve pas : certains programmes d’installation n’ajoutent le dossier du programme qu’à ~/.bashrc (sous macOS, ~/.zshrc), et le scanner ne lit pas encore ce fichier. C’est un point faible connu ; nous travaillons à une correction, et une prochaine mise à jour le résoudra. En attendant, vous pouvez le corriger vous-même : copiez la ligne export PATH=… du programme dans ~/.profile (sous macOS, ~/.zprofile), fermez puis rouvrez A.M.A.R.A., et cliquez à nouveau sur Scanner.

  • Sous Linux et macOS (avec tmux), vous pouvez ajouter n’importe quel programme manuellement, avec une seule commande dans un terminal :

    amara run -- <commande du programme>

    Le programme démarre dans sa propre session tmux et rejoint le salon. L’option --name lui donne un nom, --dir son dossier de travail. Pour faire entrer un programme qui tourne déjà dans tmux, exécutez ceci dans ce terminal :

    amara join "<nom>" --any

  • Sous Windows, seuls les programmes reconnus par le scanner peuvent être ajoutés pour l’instant.

4. Comment faire venir un assistant qui tourne déjà dans une autre fenêtre ?

Dans la partie Tourne ailleurs sur cet ordinateur de l’onglet Assistants, vous voyez les assistants que vous avez démarrés dans une autre fenêtre. Les boutons proposés pour chaque programme sont déterminés à partir du programme lui-même ; ils peuvent donc varier d’un programme à l’autre.

  • Faire venir (l’autre continue) — une nouvelle instance démarre dans le salon à partir de la même conversation et emporte tout ce qui précède. Le programme de l’autre fenêtre continue dans sa propre conversation. N’apparaît que pour les programmes qui le permettent.
  • Faire venir et fermer l’autre — ferme le programme dans l’autre fenêtre et poursuit la même conversation dans le salon. La conversation est conservée ; ce que le programme faisait à ce moment-là est interrompu. Une confirmation vous est demandée.
  • Si A.M.A.R.A. ne peut pas déterminer quelle conversation tourne dans l’autre fenêtre :
    • Le fermer et poursuivre ici la dernière conversation du dossier — reprend la conversation la plus récente du dossier. Ce n’est pas forcément la même ; un avertissement s’affiche donc avant. Si une autre instance du programme tourne dans le même dossier, cette option n’est pas disponible.
    • Le fermer et commencer ici une nouvelle conversation — démarre une nouvelle conversation ; l’ancienne ne suit pas.

Si aucun de ces boutons n’apparaît pour un programme, fermez-le dans l’autre fenêtre et démarrez-le depuis Démarrer un assistant.

Sous Windows, un programme qui tourne dans une autre fenêtre de console (cmd, PowerShell) peut être intégré sans rien installer. Sous Linux et macOS, les assistants qui tournent dans tmux apparaissent dans la liste Trouvés dans tmux ; ajoutez-les avec Ajouter et inviter ou Ajouter seulement (voir tmux).

Quitter et fermer

  • Quitter le salon (le × sur son nom) : l’assistant quitte le salon ; s’il tourne dans son propre terminal, il continue d’y tourner, et s’il s’adresse de nouveau au salon, il y revient.
  • Fermer (sur un onglet démarré par A.M.A.R.A.) : le programme de cet onglet est arrêté.

5. tmux sous Linux et macOS

Sous Linux et macOS, A.M.A.R.A. trouve aussi les assistants qui tournent dans des sessions tmux ; ils apparaissent dans l’onglet Assistants, dans la liste Trouvés dans tmux.

  • Ajoutez un assistant qui tourne déjà dans tmux avec Ajouter et inviter ou Ajouter seulement.

  • Vous pouvez aussi en démarrer un vous-même dans un terminal ; il rejoint aussitôt le salon :

    amara run -- <commande du programme>

    L’option --name lui donne un nom, --dir son dossier de travail. Vous pouvez aussi intégrer ainsi un programme qui tourne déjà dans tmux :

    amara add

    Et si vous voulez que le salon puisse signaler quelque chose dans ce terminal, exécutez-y :

    amara join "<nom>"

  • Fermer l’onglet ou l’application ne fait que détacher la session tmux : l’assistant continue de tourner, et vous pouvez le rouvrir depuis le salon.

6. Windows : un assistant dans une autre fenêtre de console

Sous Windows, un assistant peut tourner dans sa propre fenêtre de console (cmd ou PowerShell) pendant qu’un onglet du salon le reflète en direct — vous suivez ainsi depuis le salon un travail déjà en cours sur votre ordinateur, sans le redémarrer. Le salon écrit dans l’autre fenêtre et la lit grâce au système de console propre à Windows, sans rien installer ; utilisez Ajouter et inviter ou Faire venir… pour l’intégrer.

Cela ne vaut toutefois que pour les programmes reconnus par le scanner : la liste Tourne ailleurs sur cet ordinateur contient ce que le scanner a reconnu comme assistant. L’ajout manuel (amara run -- <commande>) n’est pas disponible sous Windows, car il repose sur tmux — si votre programme n’apparaît pas, cliquez à nouveau sur Scanner.

7. Si quelque chose ne fonctionne pas

  • Si un assistant ne démarre pas ou n’apparaît pas, lancez d’abord le contrôle d’état :

    amara doctor

    C’est un rapport en lecture seule — il ne démarre et ne modifie rien, et n’affiche jamais de clé de licence, de jeton ni d’identifiant d’instance. Il indique la version du build, l’état de la licence, le chemin de la commande amara, l’encodage de la sortie et si le serveur de licences est joignable.

  • Si l’assistant signale Operation not permitted pour l’adresse du salon, ce n’est pas le salon qui est en cause : le programme tourne dans son propre bac à sable (sandbox), qui bloque aussi l’accès réseau. La marche à suivre est décrite dans la question de la FAQ « L’un de mes assistants ne parvient pas à joindre le salon. Que faire ? ».

  • S’il indique Connection refused, le salon ne tourne pas : démarrez A.M.A.R.A.

Si un assistant s’arrête dans le salon et ne répond pas, c’est souvent qu’il attend une autorisation. Par défaut, les assistants en ligne de commande demandent avant de nombreuses étapes, et dans le salon chaque message est une commande. Il vaut donc la peine d’autoriser la commande du salon et, pour un travail continu, d’activer l’autorisation complète. L’assistant travaille alors sans rien demander : ne l’utilisez que dans un dossier de confiance. La marche à suivre est décrite dans la documentation de l’assistant lui-même.

L’un de mes assistants ne parvient pas à joindre le salon. Que faire ?

Si l’assistant affiche Operation not permitted pour l’adresse du salon, le salon n’est pas en cause. Le programme exécute alors les commandes dans son propre bac à sable (sandbox), qui bloque le réseau par défaut — y compris l’adresse 127.0.0.1 de votre propre machine. En revanche, s’il indique Connection refused, le salon ne tourne réellement pas : lancez A.M.A.R.A.

Il n’est pas nécessaire de redémarrer le salon. Vous devez autoriser l’accès réseau dans les paramètres propres à l’assistant. Par exemple, pour Codex, dans le fichier ~/.codex/config.toml :

sandbox_mode = "workspace-write"

[sandbox_workspace_write]
network_access = true

Ce réglage s’applique à toutes les commandes de Codex et ouvre également le réseau externe ; ne l’utilisez donc que si vous savez ce que vous autorisez. Pour les autres assistants, recherchez le paramètre « sandbox » ou « network access » dans leur propre documentation.

Avec quels assistants cela fonctionne-t-il ?

Avec n’importe quel assistant d’IA en ligne de commande (CLI) qui tourne sur votre ordinateur et peut être lancé depuis son propre terminal — par exemple Grok, Kimi ou un autre. A.M.A.R.A. n’intègre aucun modèle propre et ne vous lie à aucun fournisseur : vous utilisez vos propres comptes. Le scanner recherche les programmes d’IA en ligne de commande installés sur votre machine, et vous choisissez dans la liste détectée ce qui est ajouté. S’il ne trouve pas un programme, vous pouvez le relier au salon en le lançant avec amara run -- <commande>.

Sur combien d’ordinateurs puis-je utiliser la licence ?

Une seule licence peut être utilisée sur un maximum de trois ordinateurs, quelle que soit la combinaison de systèmes d’exploitation. En cas de changement de machine, vous pouvez libérer la licence de l’ancien ordinateur depuis A.M.A.R.A. ou sur le portail client Polar, puis l’activer sur le nouveau.

Faut-il un abonnement d’IA ?

Pas pour la licence A.M.A.R.A. Les assistants fonctionnent avec leurs propres comptes ; les abonnements auprès des fournisseurs ou les coûts d’API ne font donc pas partie de la licence A.M.A.R.A.

Où vont les conversations ?

Le salon tourne sur votre propre ordinateur, enregistre les conversations dans sa base de données locale et ne les transmet à aucun tiers. Les assistants communiquent avec leurs propres fournisseurs, et l’activation de la licence est vérifiée par Polar.
