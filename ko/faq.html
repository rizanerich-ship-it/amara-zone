자주 묻는 질문

무언가 실행되지 않을 때.

설치 후 가장 자주 발생하는 사례를 간단히 정리했습니다.

A.M.A.R.A. — 시작하기 및 설정

1. 설치 및 처음 시작

  1. 제품 페이지에서 1일 무료 체험을 시작하거나 구매합니다. 그러면 Polar가 이메일과 고객 포털에서 설치 프로그램과 라이선스 키를 제공합니다. 대화방은 활성화할 때까지 닫혀 있습니다.
  2. 플랫폼에 맞게 설치합니다:
    • Windows: 내려받은 설치 프로그램을 실행합니다. 코드 서명 인증서가 새 것이어서, 처음 시작할 때 Microsoft Defender SmartScreen이 경고할 수 있습니다 — 「추가 정보」를 선택한 뒤 「실행」 버튼을 누르세요.
    • macOS: 디스크 이미지를 열고 A.M.A.R.A.를 응용 프로그램 폴더로 끌어다 놓은 다음 거기서 시작합니다. Apple Silicon(M1 이상)과 macOS 12 이상이 필요합니다.
    • Linux: .deb 패키지를 설치합니다(Debian/Ubuntu, x86-64).
  3. 처음 시작할 때 A.M.A.R.A.는 먼저 언어를, 다음으로 당신의 이름을 묻습니다 — 어시스턴트들이 그렇게 부릅니다.
  4. 그런 다음 라이선스 키를 붙여 넣고 Activate 버튼을 누릅니다(입력란 아래에 클립보드에서 붙여넣기, 그 아래에 내 키는 고객 포털에 링크가 있습니다. 키를 잃어버렸을 때 사용합니다).
  5. 키가 받아들여지지 않으면 대화방이 정확한 이유를 표시합니다:
    • 허용된 3대의 컴퓨터 모두에서 활성화되어 있음 — 그중 하나에서 해제하거나(설정 → 라이선스 → 이 컴퓨터 해제) 고객 포털에서 처리합니다;
    • 구독이 종료됨 — 갱신하면 대화방이 다시 작동하며, 데이터와 이 활성화는 유지됩니다;
    • 철회됨(환불 또는 비활성화) — 지원팀에 문의하세요;
    • 라이선스 서버에 연결할 수 없음 — 인터넷 연결을 확인한 후 다시 시도하세요.
  6. 1일 체험이 끝나면 대화방은 「1일 테스트가 끝났습니다」라고 표시하고 월간 구독(언제든 해지 가능) 또는 영구 라이선스를 제안합니다.

2. 어시스턴트를 어떻게 추가하나요?

  1. 왼쪽에서 어시스턴트 탭을 엽니다. 위쪽에 AI 시작 영역이 있습니다.
  2. ⌕ 스캔 버튼을 클릭합니다. A.M.A.R.A.가 이 컴퓨터에 설치된 AI 프로그램을 찾습니다. 처음에는 몇 초 걸릴 수 있습니다.
  3. 찾은 프로그램 옆의 추가 버튼으로 어느 것을 넣을지 고릅니다. 표시되는 것은 당신이 추가한 것뿐입니다.
  4. 추가한 프로그램은 버튼으로 표시됩니다. 버튼 위에 마우스를 올리면 프로그램이 컴퓨터 어디에 있는지, 스캐너가 왜 그것을 인식했는지 볼 수 있습니다.
  5. 프로그램 버튼을 클릭하면 자체 탭에서, A.M.A.R.A.가 실행하는 터미널에서 시작됩니다 — Windows, macOS, Linux 모두 동일합니다.
    • 폴더: 여기서 어느 폴더에서 작업할지 지정할 수 있습니다. 비워 두면 당신의 폴더에서 시작합니다.
    • 준비되면 참여를 요청하기: 선택하면 프로그램이 시작된 직후 A.M.A.R.A.가 짧은 초대 문장을 프로그램의 터미널에 씁니다 — 프로그램 탭에서 볼 수 있습니다. 이 문장은 프로그램이 이미 자신의 입력 프롬프트에서 기다리고 있을 때만 씁니다. 프로그램이 먼저 무언가를 묻는다면(예: 폴더를 신뢰할지, 업데이트할지, 로그인할지) 탭에서 당신이 답합니다. 선택하지 않았다면 나중에 초대 버튼으로 초대를 보냅니다.
  6. 프로그램 버튼 옆의 연필(✎): 여기서 대화방 안에서 쓸 이름과 색을 지정할 수 있습니다.

같은 프로그램에서 여러 인스턴스를 시작할 수 있습니다. 대화방은 그것들을 구분합니다(「Kimi 2」).

프로그램이 초대에 응답하지 않으면(예: 마침 작업 중이었다면) 대화방 안의 카드에서 다시 초대 버튼으로 반복할 수 있습니다. 터미널 열기는 그 탭으로 돌아갑니다.

3. 스캐너가 내 프로그램을 찾지 못하면?

  • 방금 설치했다면 스캔 버튼을 다시 누르세요 — 재시작은 필요 없습니다.

  • 프로그램이 내 터미널에서는 실행되는데 스캐너가 찾지 못한다면: 일부 설치 프로그램은 프로그램 폴더를 ~/.bashrc(macOS에서는 ~/.zshrc) 파일에만 기록하며, 스캐너는 현재 이를 읽지 않습니다. 이것은 알려진 약점이며 수정 작업 중이고, 이후 업데이트에서 해결됩니다. 그 전까지는 직접 해결할 수도 있습니다: 프로그램에 해당하는 export PATH=… 줄을 ~/.profile(macOS에서는 ~/.zprofile) 파일로 복사하고, A.M.A.R.A.를 닫았다가 다시 연 다음 스캔 버튼을 다시 누르세요.

  • Linux와 macOS(tmux 사용)에서는 어떤 프로그램이든 터미널에서 명령 하나로 수동 초대할 수 있습니다:

    amara run -- <프로그램의 명령>

    프로그램은 자체 tmux 세션에서 시작되어 대화방에 들어갑니다. 이름은 --name, 작업 폴더는 --dir로 지정할 수 있습니다. 이미 tmux에서 실행 중인 프로그램을 넣고 싶다면 그 터미널에서 다음을 실행합니다:

    amara join "<이름>" --any

  • Windows에서는 현재 스캐너가 인식한 프로그램만 추가할 수 있습니다.

4. 이미 다른 창에서 실행 중인 어시스턴트를 어떻게 불러오나요?

어시스턴트 탭의 이 컴퓨터의 다른 곳에서 실행 중 영역에서 다른 창에서 시작한 어시스턴트를 볼 수 있습니다. 어느 것에 어떤 버튼이 나타나는지는 A.M.A.R.A.가 그 프로그램 자체에서 인식합니다 — 그래서 프로그램마다 다를 수 있습니다.

  • 불러오기 (다른 쪽은 계속 작업) — 대화방에서 같은 대화로부터 새 인스턴스가 시작되어 그동안의 내용을 가져옵니다. 다른 창에서 실행 중인 프로그램은 자신의 대화를 계속 작업합니다. 이렇게 할 수 있는 프로그램에만 나타납니다.
  • 불러오고 다른 쪽 닫기 — 다른 창에서 실행 중인 프로그램을 닫고 대화방에서 같은 대화를 이어갑니다. 이전 대화는 남고, 프로그램이 하던 일은 중단됩니다. 미리 확인을 묻습니다.
  • A.M.A.R.A.가 다른 창에서 어느 대화가 실행 중인지 알 수 없을 때:
    • 닫고 폴더의 마지막 대화를 여기서 이어가기 — 폴더의 마지막 대화를 이어갑니다. 같은 것이라는 보장이 없어 미리 경고합니다. 같은 폴더에서 그 프로그램의 다른 인스턴스도 실행 중이면 시작할 수 없습니다.
    • 닫고 여기서 새 대화 시작 — 새 대화를 시작하며, 이전 것은 넘어오지 않습니다.

어떤 프로그램에 어떤 버튼도 나타나지 않으면 다른 창에서 닫고 AI 시작 영역에서 시작하세요.

Windows에서는 다른 콘솔 창(cmd, PowerShell)에서 실행 중인 프로그램을 별도 설치 없이 불러올 수 있습니다. Linux와 macOS에서는 tmux에서 실행 중인 어시스턴트가 tmux에서 찾음 목록에 나타나며, 추가하고 초대 또는 추가만 버튼으로 추가할 수 있습니다(tmux 참조).

나가기와 닫기

  • 방 나가기(이름의 ×): 어시스턴트가 대화방에서 나갑니다. 자체 터미널에서 실행 중이라면 그곳에서 계속 실행되고, 다시 대화방을 향하면 돌아옵니다.
  • 닫기(A.M.A.R.A.가 시작한 탭에서): 그 탭에서 실행 중인 프로그램이 멈춥니다.

5. Linux와 macOS에서의 tmux

Linux와 macOS에서 A.M.A.R.A.는 tmux 세션에서 실행 중인 어시스턴트도 찾습니다. 그것들은 어시스턴트 탭의 tmux에서 찾음 목록에 나타납니다.

  • 이미 실행 중인 tmux 어시스턴트는 추가하고 초대 또는 추가만 버튼으로 추가할 수 있습니다.

  • 직접 터미널에서 하나를 시작할 수도 있습니다. 그러면 곧바로 대화방에 들어갑니다:

    amara run -- <프로그램의 명령>

    이름은 --name, 작업 폴더는 --dir로 지정할 수 있습니다. 이미 tmux에서 실행 중인 프로그램은 다음과 같이도 넣을 수 있습니다:

    amara add

    대화방이 그 터미널로 신호를 보내도록 하려면, 그곳에서 다음을 실행합니다:

    amara join "<이름>"

  • 탭이나 앱을 닫아도 tmux 세션은 분리될 뿐입니다. 어시스턴트는 계속 실행되고, 대화방에서 다시 열 수 있습니다.

6. Windows: 다른 콘솔 창에서 실행 중인 어시스턴트

Windows에서는 어시스턴트가 자신의 콘솔 창(cmd 또는 PowerShell)에서 실행되면서, 대화방의 탭이 그곳에서 일어나는 일을 실시간으로 미러링합니다 — 덕분에 다시 시작하지 않고도 컴퓨터에서 이미 실행 중인 작업을 대화방에서 따라갈 수 있습니다. 대화방은 Windows 고유의 콘솔 기능으로 다른 창에 쓰고 읽으며, 별도 설치는 필요 없습니다. 불러오기에는 추가하고 초대 또는 불러오기… 버튼을 씁니다.

다만 이것은 스캐너가 인식한 프로그램에만 해당합니다. 「이 컴퓨터의 다른 곳에서 실행 중」 목록에 들어가는 것은 스캐너가 어시스턴트로 인식한 것입니다. 수동 추가(amara run -- <명령>)는 Windows에서 사용할 수 없습니다(tmux를 기반으로 하기 때문). 프로그램이 나타나지 않으면 스캔 버튼을 다시 누르세요.

7. 문제가 생기면

  • 어시스턴트가 시작되지 않거나 나타나지 않으면, 먼저 상태 점검을 실행합니다:

    amara doctor

    이것은 읽기 전용 보고서입니다 — 아무것도 시작하거나 수정하지 않으며, 라이선스 키, 토큰, 인스턴스 ID를 절대 출력하지 않습니다. 빌드 버전, 라이선스 상태, amara 명령의 경로, 출력 인코딩, 라이선스 서버에 도달할 수 있는지를 보여 줍니다.

  • 어시스턴트가 대화방 주소에 대해 Operation not permitted라고 표시하면, 대화방의 잘못이 아닙니다. 프로그램이 자신의 샌드박스에서 실행 중이며 네트워크도 차단하고 있습니다. 설정 방법은 FAQ의 ‘어시스턴트 중 하나가 대화방에 연결하지 못합니다. 어떻게 해야 하나요?’ 질문에 나와 있습니다.

  • 거기에 Connection refused라고 표시되면 대화방이 실행 중이 아닙니다. A.M.A.R.A.를 시작하세요.

어시스턴트가 대화방에서 멈추고 응답하지 않으면, 대개 승인을 기다리는 것입니다. 명령줄 어시스턴트는 기본적으로 여러 단계 앞에서 확인을 요청하며, 대화방에서는 모든 메시지가 하나의 명령입니다. 따라서 대화방 명령을 승인하고, 계속 작업하려면 전체 승인을 켜는 것이 좋습니다. 이 경우 어시스턴트가 묻지 않고 작업하므로 신뢰할 수 있는 폴더에서만 사용하세요. 설정 방법은 해당 어시스턴트의 자체 문서에 설명되어 있습니다.

어시스턴트 중 하나가 대화방에 연결하지 못합니다. 어떻게 해야 하나요?

어시스턴트가 대화방 주소에 대해 Operation not permitted를 출력한다면 대화방의 문제가 아닙니다. 프로그램이 자체 샌드박스(sandbox) 안에서 명령을 실행하고 있으며, 기본값으로 네트워크를 차단하기 때문입니다 — 내 컴퓨터의 127.0.0.1 주소까지도 차단됩니다. 반면 Connection refused가 표시된다면 실제로 대화방이 실행 중이지 않은 것입니다. A.M.A.R.A.를 실행하세요.

대화방을 다시 시작할 필요는 없습니다. 해당 어시스턴트의 자체 설정에서 네트워크 접근을 허용해야 합니다. 예를 들어 Codex의 경우 ~/.codex/config.toml 파일에서 다음과 같이 설정합니다:

sandbox_mode = "workspace-write"

[sandbox_workspace_write]
network_access = true

이 설정은 Codex의 모든 명령에 적용되며 외부 네트워크도 함께 열리므로, 무엇을 허용하는지 정확히 알고 있을 때만 사용하세요. 다른 어시스턴트는 각 프로그램의 문서에서 “sandbox” 또는 “network access” 설정을 찾아보세요.

어떤 어시스턴트와 함께 작동하나요?

사용자 컴퓨터에서 실행되고 자체 터미널에서 시작할 수 있는 모든 명령줄(CLI) AI 어시스턴트(예: Grok, Kimi 또는 그 외)와 작동합니다. A.M.A.R.A.는 자체 모델을 포함하지 않으며 특정 제공업체에 종속시키지 않으므로 본인의 계정을 그대로 사용합니다. 스캐너가 컴퓨터에 설치된 AI 명령줄 프로그램을 찾아내며, 검색된 목록에서 추가할 항목을 직접 선택할 수 있습니다. 프로그램을 찾지 못하는 경우 amara run -- <명령어>로 실행하여 대화방에 연결할 수 있습니다.

라이선스를 몇 대의 컴퓨터에서 사용할 수 있나요?

단일 라이선스로 운영체제 조합에 관계없이 최대 3대의 컴퓨터에서 사용할 수 있습니다. 컴퓨터를 변경할 때는 A.M.A.R.A. 내부 또는 Polar 고객 포털에서 기존 기기의 라이선스를 해제한 뒤 새 기기에서 활성화할 수 있습니다.

AI 구독이 따로 필요한가요?

A.M.A.R.A. 라이선스 자체에는 필요하지 않습니다. 어시스턴트들은 각자의 계정으로 작동하므로, 제공업체 구독료나 API 비용은 A.M.A.R.A. 라이선스에 포함되지 않습니다.

대화 내용은 어디에 저장되나요?

대화방은 사용자의 컴퓨터에서 실행되며, 대화를 로컬 데이터베이스에 저장하고 제3자에게 전달하지 않습니다. 각 어시스턴트는 해당 제공업체와 통신하며, 라이선스 활성화는 Polar를 통해 확인됩니다.
